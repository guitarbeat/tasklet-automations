# System Rethink — July 9, 2026

## The Honest Assessment

This automation was built for a world that no longer exists.

### What it was built for
A firehose of Jules-generated PRs (15+ open at once) in PhD-Writing that needed
triage, rebasing, conflict resolution, and one-at-a-time session management.
Mission control made sense: queue, lifecycle stepper, activity log, health grades.

### The world today
| Signal | State |
|---|---|
| Open PRs (both repos) | ~0 — one ImgBot PR appeared today |
| Jules queue | 111 entries, **all resolved**, dead since Jun 25 |
| Activity log | Last entry Jun 25 (2 weeks silent) |
| Scheduled automations | **Zero. All 3 triggers are gone.** |
| Dashboard | Beautiful mission control… for an empty airport |

**Surprise finding #1:** The three scheduled automations (Monday rebase scan,
daily repo sync, daily health alerts) no longer exist. Nothing has been running
autonomously. The only scans happening are the ones Aaron manually requests.

**Surprise finding #2:** `bledsoe-mobile-notary` has **6 duplicate open issues**
titled "Branch cleanup: manual review needed" (May 18 → Jul 6), filed roughly
weekly by a GitHub Action. Nobody is triaging them; they just accumulate.

**Surprise finding #3:** A fresh PR exists right now — PhD-Writing **#674
"[ImgBot] Optimize images"** (opened Jul 9). The dashboard would show it, but
no automation noticed it.

## The Rethink: from Mission Control → Repo Caretaker

The job is no longer "manage a PR firehose." The job is **"keep two quiet repos
healthy with near-zero human attention."** That means:

### 1. One trigger, not three (rebuild what silently vanished)
A single **weekly caretaker run** (Mondays 9 AM CT) that does everything:
- Scan open PRs → classify, queue, ping Jules if stale
- Scan open issues → flag duplicates/noise (like the 6 branch-cleanup clones)
- Check default-branch CI status
- **Only email Aaron if something needs action.** Silence = health.

### 2. Dashboard stays, but demoted
It's already compact and good. It becomes the on-demand view, not the center
of gravity. No changes needed — stop polishing it.

### 3. Clean up the noise now
- Close/consolidate the 6 duplicate branch-cleanup issues into one
- Handle PR #674 (ImgBot — likely safe to track in queue)
- Normalize the `repo` naming inconsistency in jules_queue (one UPDATE)

### 4. Retire dead weight
- `jules-sessions.json` (4.6 MB, from April) → delete
- Subagents for abandoned workflows (`delete-jules-sessions`, `post-jules-update-comments`, `scan-dashboard-styling`, `build-pr-dashboard`) → delete
- Keep: `stale-pr-scan`, `pr-health-alerts` (merge into one caretaker subagent), `sync-repo`

### What I'm NOT proposing
- More dashboard polish (diminishing returns; it's good)
- Daily triggers (repos are too quiet to justify daily runs)
- Reviving the bulk Jules ping model (already abandoned for good reason)

## Bottom line
Rebuild the automation layer that silently disappeared, but simpler: **one
weekly caretaker trigger + one consolidated subagent + email-only-when-actionable.**
The system should be judged by how rarely it needs to speak, not how much it shows.
